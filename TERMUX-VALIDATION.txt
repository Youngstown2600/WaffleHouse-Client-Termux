WaffleHouse-Termux 1.0r1 — source/parity validation
================================================

Release target
--------------
Native Termux CLI based on the WaffleHouse-Client 5.1 shared protocol/core
implementation, with the known-good native Android/Termux runtime changes from
Termux Build 0.9 preserved where desktop 5.1 behavior is not directly portable.

Static regression coverage included in this archive
----------------------------------------------------
1. Release identity and CLI-only build boundaries.
2. AIM/OSCAR 5.1 NINA network profiles/bootstrap markers.
3. Native OSCAR idle/presence and diagnostic modes.
4. OSCAR voice engine and CLI command wiring, using native PortAudio rather than Qt Multimedia/Gui.
5. Unified contact/history/capability core.
6. Current SIP compatibility including Asterisk chan_sip and concurrent-account
   capacity assumptions.
7. Termux PJSIP GUID, PortAudio, null-device, speaker-only, runtime-path, and
   password-persistence safeguards.
8. Exact Telnet/BBS columns/rows, CSI outer-terminal resize request, live
   TIOCGWINSZ/resizeterm detection, visible-grid fallback, and NAWS updates.
9. Responsive 24x6 phone layout and adaptive popup sizes.
10. Termux shared Downloads, browser handoff, media-player integration, and
    installer/update aliases.
11. Qt dependency boundary: Termux requires Qt Core + Network only; Qt Multimedia/Gui are not part of the native CLI build.

Run from the source root:

  ./tests/run-termux-tests.sh
  ./tests/termux_sip_password_persistence_test.sh
  ./tests/termux_sip_runtime_test.sh

Important runtime note
----------------------
The archive-preparation environment is Linux, not Android/Termux. The included
checks can validate source parity, shell syntax, and merge invariants here, but
they cannot substitute for compiling against Termux's Qt/PJSIP packages or for
placing a real SIP/AIM/Telnet call/session on an Android phone. Perform the final
build and live audio/network smoke test inside Termux with ./build.sh.
